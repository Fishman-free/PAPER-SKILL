# 摘要范式

> 摘要不是论文的压缩，是**独立的说服材料**。
> 评委可能只精读这一页——这不是"否则被淘汰"的恐吓，而是**唯一一次低成本说服他的机会**。

---

## 一、官方规定（只有格式）

《论文格式规范》2026 修订稿第三条：

- 摘要专用页在**纸质版第 3 页**（第 1 页承诺书、第 2 页编号专用页）；**电子版第 1 页**
- 内容含**标题和关键词**；**原则上不超过一页**；**无需翻译成英文**
- 页码从摘要页开始，页脚中部，阿拉伯数字从「1」连续编号

**官方对摘要没有任何分值规定、没有权重、没有否决权条款。**

摘要的地位来自阅卷实践（多位有评阅经历的高校教授在讲座中一致强调，见 `02-评阅标准与红线.md` §3.2）。

---

## 二、官方训练材料的摘要五要素

高校训练材料（C 级，多校一致）要求摘要包含：

| # | 要素 | 说明 |
|---|------|------|
| 1 | **模型的数学归类** | 属什么数学问题：优化 / 预测 / 评价 / 分类 / 统计推断 / 机理分析 |
| 2 | **建模思想** | 你的建模思路是什么 |
| 3 | **算法思想** | 怎么求解 |
| 4 | **建模特点** | 模型优点、方法特点、**结果检验、灵敏度分析、模型检验** |
| 5 | **主要结果** | 数值结果与结论，**必须回答题目所问的全部问题** |

> ⚠️ 第 5 条是硬要求。**题目问了三问，摘要必须有三问的答案。** 漏答任何一问，评委立刻知道你没做完题。

---

## 三、结构公式（段数固定）

```
第 1 段  总起        2-4 句：背景一句 + 本文用了哪类方法 + 解决什么问题
第 2 段  问题一      针对问题一，<方法>，<怎么做>，<得到什么数值>
第 3 段  问题二      针对问题二，……
第 4 段  问题三      针对问题三，……
第 5 段  评价（可选） 最后，我们对提出的模型进行全面的评价……
关键词   一行        3-6 个：模型名 + 算法名 + 核心概念
```

**注意**：每问一段，不要合并。段落是给评委的视觉锚点——他一眼扫到「针对问题三」，就知道你有三问的结果。

## 四、每个问题段落的三件套（缺一不可）

| 要件 | 要求 | ✅ 好的写法 | ❌ 扣分写法 |
|------|------|-----------|-----------|
| **① 模型/方法名** | 具体名称 | `t 分布假设检验`、`决策树模型`、`线性模拟退火`、`牛顿迭代反演法`、`遗传算法` | 「建立了数学模型」「运用了相关算法」 |
| **② 求解步骤** | 2-3 句说清先干什么、再干什么 | 「首先假设合格品和次品分别以 0 和 1 标定……接着根据棣莫弗-拉普拉斯定理……由于数学期望已知而方差未知，我们将其构造为 t 分布」 | 只有模型名字，没有过程 |
| **③ 数值结果** | **必须带数字和单位** | `1600 个`、`176 个次品`、`2646 个`、`291 个`、`35934 元`、`813682 元`、`7.544μm`、`0.95 置信区间` | 「结果较好」「方案较优」「得到满意结果」 |

> **检验方法**：把每问的段落遮住最后一句，如果剩下的内容看不出你算出了什么，就是缺第 ③ 件。

### 「洗苹果」判据（最直观的反复述测试）

假设题目要求你「洗苹果」。下面三种写法都是**复述任务**，不是报告结果：

> ❌「我们洗了苹果」　❌「我们很好地洗了一个苹果」　❌「我们的苹果洗得很干净」

这些句子的共同问题：**换到另一篇论文前面也不能说是错的**——它们没有提供任何只属于你的信息。

正确的写法（同一件事，写出细节）：

> ✅ 我们使用纯净水作为水源，先去泥，简单冲洗后，使用某某果蔬洗洁剂清洗，最后漂洗晾干。
> 检测结果表明，经此方法清洗后的苹果，表面杂质、细菌、微生物含量低于 XX，洗洁剂残留量
> 不超过 YY，低于国家标准 ZZ。

**即使方法很简单，也要写清楚过程与观测结果**：

> ✅ 直接使用流动的自来水作为水源，不做预处理，只洗一遍，未做其他测试，目测及手感
> 苹果表面无异物。使用该方法不需要使用额外设备或添加剂，平均每分钟可洗 2 个苹果，
> 清洗过程不会引入其他化学物品残留。

> **结论：无论方法简单还是复杂，摘要都应该写清楚过程与具体观测值，优劣留给评委去评价。**

**真实反例**（某年国赛 A 题摘要的问题段落）：

> ❌「根据数据分布特征进行分类讨论，确定该 CT 系统使用的 X 射线的 180 个方向」
>
> 点评：**什么样的分类讨论可以得到 180 个方向？难以想像。**
>
> ❌「再通过部分特殊数据的分析和代数求解，从而解得探测器单元之间的距离」
>
> 点评：**用到了哪些特殊数据，距离是多少？**
>
> 这两句几乎是在复述题目的要求，只是换了一种说法，增加了一些**笼统的方法名字**，
> 声称完成了任务，但没有给出具体结果。

**自检**：把摘要里的每一句「我们做了 X」改写成「我们用了什么方法、得到什么数」。
如果改写不出来，说明你只写了任务，没写结果。

## 五、三条获奖摘要的段落签名（可直接套用）

### 签名 A：模型名前置型（最通用，推荐）

> 来源：B196（生产决策题）

```
问题X中，针对<对象>的<问题性质>，我们<设计了/建立了>基于<方法>的<模型名>。
首先，<第一步>……接着，<第二步>……然后，<第三步>……
例如，<一个具体算例>，最优决策为<具体决策>，这样可以在<条件>下，
获得<数值结果>。
```

**实例**：

> 问题二中，针对企业生产过程中的决策问题，我们建立了决策树模型，并采用蒙特卡洛模拟和蚁群算法进行求解。首先，将生产过程分解为一系列决策节点……然后，计算每条路径的成本和收益，从而得到每条路径的利润。通过随机模拟所有可能的决策路径，并计算每条路径的期望利润，我们可以找到最大化利润的路径。为了进一步提高求解效率和解的质量，我们引入了蚁群算法对蒙特卡洛模拟进行优化……例如，问题二的情况一中，最优决策为对零件 1 进行检测，对零件 2 不进行检测，对成品不进行检测，对不合格成品进行拆解。这样可以在 1000 次采购 2000 个零件 A 和 B 进行制作售卖的情况下，获得平均利润 35934 元。

**威力所在**：「例如」后面**必须挂一个真实算例 + 一个真实数字**。评委扫读时眼睛就停在这个数字上。

### 签名 B：统计推断递进型（适合统计/检验类）

> 来源：B196 问题一

```
问题X中，针对<对象>的<指标>，我们设计了基于<分布假设>的<检验方案>。
首先，假设<离散化处理>，则可认为<变量>服从<分布>。
接着，根据<定理>，结合<背景>，将<变量>近似认为是<分布>。
由于<条件 A> 已知而<条件 B> 未知，我们将其构造为<分布>，以便进行<检验>。
通过<步骤一>、<步骤二>，我们可以判断<结论>。
最终得到，在 <置信水平 1> 下，需要<动作>，若<阈值条件>，则<接受/拒绝>；
在 <置信水平 2> 下，需要<动作>，若<阈值条件>，则<接受/拒绝>。
```

**威力所在**：**同一问题给两个置信水平下的两套答案**。这直接展示了模型的完整性，而不是只算一个点。

### 签名 C：双路线交叉验证型（适合机理/物理类）

> 来源：B060（红外干涉测厚）

```
[总起] 本文通过研究<问题>，提出了一种基于<方法 A>、同基于<方法 B>
       进行<结果>交叉印证的解决路径。

[问题N] 对于问题N，在……建立的模型上，设计了两个求解路线
        （1）<路线 A 名称>：……给出<结果>为 <数值 1>
        （2）<路线 B 名称>：……给出<结果>为 <数值 2>
            作为<数值 1> 的较好印证值
```

**威力所在**：把**两个独立解法的数值并列**，用一致性证明可信度。评委看到"交叉印证"四个字就知道作者有科学素养。

### 签名 D：多阶段迭代降维型（适合流程/决策类）

> 来源：B195（生产决策）

```
[问题N] 对于问题N，<定性关系>，利用<思想>将<问题>转化为<简化问题>，
        降低<难度>。利用<公式/定理>考虑<关键因素>……
        建立以<目标>为目标函数优化模型……确定 <N> 个决策变量：……
        得到<结果>（仿真初始<规模>）：<结果 1>；<结果 2>。
```

**威力所在**：显式写出**难度管理**（「降低仿真难度」）和**问题规模**（「确定 16 个决策变量」「仿真初始配件数为各 10000 件」）。评委据此判断你的工作量和工程可行性的边界。

## 六、摘要的三个高频雷区

### 雷区 1：背景段写成赛题复述

B196 第一段只有 **2 句**：

> 在当前市场竞争愈发严峻的大环境下，企业如何在确保产品品质的前提下有效降低生产成本，已成为其持续发展与立足市场的核心议题。本文以一家电子产品制造企业为例，深入分析其在生产流程中需要做出的策略选择。

第二句立刻进入「本文以……为例」。**背景不是越多越好，超过 4 句就挤掉了结果的空间。**

### 雷区 2：只写模型不写结果

每个问题段落**必须以数值、方案或明确结论收尾**。没有数字的段落等于空转。

### 雷区 3：各问之间没有递进关系

优秀摘要会显式写出依赖：

| 论文 | 依赖表述 |
|------|---------|
| B195 | 「沿用问题二结论」 |
| B195 | 「利用迭代思想将流程决策问题转化为多阶段问题，**降低仿真难度**」 |
| B060 | 「作为直接计算值 7.544μm 的**较好印证值**」 |
| B196 | 「**为了进一步提高求解效率和解的质量**，我们引入了蚁群算法对蒙特卡洛模拟进行优化」 |

写出问题之间的**数学依赖**，而不是并列罗列。

## 七、关键词

- **数量**：3–6 个（模板建议 3～5 个）
- **构成**：核心模型名 + 关键算法名 + 研究对象/核心概念

**实例对照**：

| 论文 | 关键词 |
|------|--------|
| B195 | 线性模拟退火　多阶段决策　模拟仿真　贝叶斯统计 |
| B196 | 假设检验　蒙特卡洛模拟　蚁群算法　遗传算法　精英策略　3σ原则 |

**反面**：「数学建模」「优化」「分析」——这些词不提供任何检索信息。

## 八、摘要打磨流程

> ⚠️ **摘要必须最后写，且要预留 ≥ 2 小时反复打磨。**

### Step 1：先写「结果清单」

在正文完成前就开始积累。正文每算出一个结果，就往清单里加一行：

```
问题一：最优方案 = ?，关键数值 = ?
问题二：最优方案 = ?，关键数值 = ?
问题三：最优方案 = ?，关键数值 = ?
```

### Step 2：按结构公式搭骨架

```
[总起] ______
[问题一] 针对问题一，______
[问题二] 针对问题二，______
[问题三] 针对问题三，______
[评价] 最后，______
[关键词] ______
```

先填空，不修饰。

### Step 3：逐问检查三件套

对每一问问自己：

- [ ] 模型/方法名写具体了吗？（不是「相关算法」）
- [ ] 求解步骤有 2-3 句吗？（先干什么、再干什么）
- [ ] **有数字和单位吗？**

### Step 4：检查递进关系

- [ ] 各问之间的依赖写出来了吗？
- [ ] 有没有「沿用」「推广」「作为印证」这类连接词？

### Step 5：删冗余

- [ ] 背景段 ≤ 4 句
- [ ] 无「结果较好」「模型合理」等模糊表述
- [ ] 无只出现一次、不提供信息的话

### Step 6：验证一致性（关键）

- [ ] 摘要里的每个数字，都能在正文找到对应
- [ ] **摘要里的每个数字，都能在附录代码的输出中找到**
- [ ] 摘要的模型名与正文第 5-7 章的模型名完全一致
- [ ] 摘要里没有正文没有的结论

> ⚠️ **规范第五条**：程序运行结果与论文不符，**可能被取消评奖资格**。这一条同样适用于摘要数值。

### Step 7：篇幅与格式

- [ ] **不超过一页**（硬上限）
- [ ] 含标题 + 摘要正文 + 关键词
- [ ] **无英文摘要**
- [ ] 无身份/学校/赛区信息

## 九、摘要自查表（打印出来逐条勾）

**结构**
- [ ] 有总起段（2-4 句，背景不超过一半）
- [ ] 每一问单独一段
- [ ] 顺序与题目一致（问题一 → 二 → 三）
- [ ] 有可选的模型评价结尾段
- [ ] 关键词 3-6 个，含具体模型/算法名

**内容**
- [ ] 每一问有**具体的模型/方法名称**
- [ ] 每一问有**求解步骤**（2-3 句）
- [ ] 每一问有**带单位的具体数值**或明确方案
- [ ] **题目问的每一问都有答案**（不遗漏）
- [ ] 写出了问题之间的递进/依赖关系
- [ ] 提到了结果检验或灵敏度分析

**反模式**
- [ ] 无大段赛题复述
- [ ] 无「结果较好」「得到满意结果」等模糊表述
- [ ] 无空泛的模型评价套话
- [ ] 无无意义的过高精度数字

**合规**
- [ ] 不超过一页
- [ ] 无英文摘要
- [ ] 无身份/学校/赛区信息
- [ ] 每个数字与正文、代码输出一致
